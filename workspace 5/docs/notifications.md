# Будущая архитектура уведомлений

> Документ описывает только будущую модель. В этапе 5 ничего из этого не реализуется.

## Цель
Своевременно напоминать пользователю о важных шагах личного плана поступления.

## Типы будущих уведомлений
- приближающийся дедлайн;
- дедлайн сегодня;
- просроченная задача;
- незавершенная задача;
- новое мероприятие;
- изменение прогресса.

## Будущие каналы доставки
- уведомления на сайте;
- Telegram;
- email;
- push.

## Планируемая логика (в будущем)
1. Система проверяет личный план пользователя (задачи, даты, прогресс).
2. Определяет, есть ли событие, которое требует напоминания.
3. Формирует короткое и понятное сообщение.
4. Отправляет сообщение в выбранные пользователем каналы.
5. Учитывает частоту уведомлений и тихие часы.

## Требования к безопасности и приватности
- Уведомления формируются только на основе данных владельца аккаунта.
- Пользователь управляет подписками и может отключить любой канал.
- История сообщений хранится ограниченно и только по необходимости.

## Что не реализовано в этапе 5
- реальная отправка уведомлений;
- интеграции с внешними сервисами;
- фоновые задачи и расписания;
- рабочие каналы Telegram/email/push.
